# Sabella 0.1.0

Sabella 0.1.0 is the initial private Swift Package Manager release of the
shared Apple-native design system. The package remains pre-1.0: its public API
is usable by authorized consumers but may evolve in later `0.x` releases.

## Public surface

- The `Sabella` library product provides native SwiftUI tokens, controls,
  feedback, navigation, data-display, chart, overlay, layout, and adaptive
  application-shell contracts.
- `SabellaCatalog` provides the searchable, platform-native component catalog
  and catalog-coverage release gate.
- `SabellaShellExamples` provides runnable tab and administration shell
  examples.
- Consumer applications link only `Sabella`; the catalog, coverage support,
  and shell example targets are not transitive library dependencies.
- On tvOS, `SabellaTVLivePlayer` offers an additive playback-activity callback
  whose `Sendable` channel/state value normalizes AVPlayer and KSPlayer. Only
  `.playing` means media is advancing; waiting, buffering, pause, failure, and
  teardown remain explicitly non-playing.

## Compatibility

- Swift tools 6.0
- macOS 14 or later
- iOS and iPadOS 17 or later
- tvOS 17 or later
- Compatible consumer range: `>= 0.1.0, < 0.2.0`

Compatible fixes may be published as `0.1.x`. A breaking public API change
before 1.0 requires a new `0.x.0` minor release. Published tags are immutable;
a correction is always a later patch or minor version.

## Installation

Authorized private consumers add:

```swift
.package(
    url: "https://github.com/gaulatti/sabella.git",
    .upToNextMinor(from: "0.1.0")
)
```

Application targets depend only on the `Sabella` product from the `Sabella`
package. GitHub developer or CI credentials must already grant access to the
private repository; no token, deploy key, or credential belongs in source,
project files, or package documentation.

## Known platform exceptions

Sabella uses native Apple interaction contracts rather than forcing identical
implementations across platforms. The catalog documents tvOS exclusions for
date-range and file-input controls because the underlying native APIs are not
available there. Other platform differences preserve safe areas, keyboard and
pointer behavior, Dynamic Type, accessibility, and television focus/remote
interaction.
